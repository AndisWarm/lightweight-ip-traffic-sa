## 1. 功能成果

### 1.1 登录鉴权与权限管理

- 实现登录、退出、当前用户查询和 JWT 签发。
- 通过 JWT 中间件保护业务接口，并通过 JWT 黑名单处理退出后的令牌失效问题。
- 支持 `ADMIN`、`MANAGER`、`USER` 三类角色，对用户管理、安全配置、任务操作、审计日志和安全数据查看进行差异化授权。
- 实现用户启停、密码重置和系统操作审计，满足安全系统的基本可追溯要求。

### 1.2 安全任务闭环

- 支持创建、查询、筛选、详情查看和删除 IP 安全检测任务。
- 任务按 `PENDING`、`RUNNING`、`SUCCESS`、`FAILED` 等状态组织，前端可以根据任务状态查看采集和评分进度。
- 任务创建后加载运行时安全配置，依次执行基础画像、信誉、攻击面和流量行为采集，再完成归一化、评分、预警和结果落库。
- 任务详情统一展示目标 IP、基础画像、来源链、证据项、评分因子、流量摘要和预警信息，形成结果回溯闭环。

### 1.3 IP 多源特征采集

#### 基础画像：GeoLite2 + RDAP

- 优先从本地 GeoLite2 Country、City、ASN 数据库读取国家、地区、城市、经纬度、ASN 和组织信息。
- 使用 RDAP 补充 IP 注册组织、网段和联系人等信息。
- 支持 RDAP 主端点和备用端点轮询，外部请求失败时记录降级原因，不阻断默认任务。

#### 信誉风险：本地黑名单 + 外部增强

- 默认读取本地黑名单和 CIDR 名单，保证离线演示和基础部署场景可用。
- AbuseIPDB 作为可选增强数据源，未配置、超时或调用失败时回退到本地信誉结果。
- 将来源名称、命中情况、返回分数和降级原因保存为可解释证据。

#### 攻击面：有限端口探测 + Nmap 增强

- 使用 Go 原生 TCP 探测检查有限端口集合，控制端口数量、并发数和单端口超时，避免把重型扫描作为默认依赖。
- Nmap 作为可选增强能力；未安装、执行失败或超时时回退到有限端口探测。
- 根据开放端口、高危端口和地理风险标记计算攻击面风险。

### 1.4 可解释风险评分

- 将采集结果归一化为四类风险因子：基础属性风险、信誉风险、攻击面风险和行为风险。
- 采用“多维度加权评分 + 规则调整”的模型计算最终得分，并映射为 `LOW`、`MEDIUM`、`HIGH`、`CRITICAL` 等风险等级。
- 评分结果显式保存 `baseScore`、`reputationScore`、`attackSurfaceScore`、`behaviorScore`、`ruleAdjustmentValue`、`algorithmVersion` 和 `weightProfile`。
- 当最终评分达到高风险阈值时自动生成预警，并在预警详情中展示评分摘要、触发原因和关联证据。
- 评分权重和风险阈值支持配置化管理，避免调整规则时修改业务代码。

### 1.5 流量增强分析

- 基于 `gopacket` 实现 `pcap/pcapng` 文件解析，支持按目标 IP 匹配相关报文和会话。
- 支持短时在线抓包，结合 Npcap 和网卡枚举接口完成真实网卡采集路线。
- 提取报文数、字节数、会话数、协议分布、DNS 查询、HTTP Host/Method、TLS 握手、端口密度、方向性、突发流量、扫描倾向和载荷熵等特征。
- 将流量结果接入行为风险评分、任务详情、历史记录、总览趋势和任务级证据回溯。
- 流量能力采用 `disabled`、`sample`、`offline_pcap`、`online_capture` 多模式设计，增强能力不可用时不会阻断默认 IP 检测主链路。

### 1.6 流量数据模型与实时监控

- 落地 `sec_flow_collection`、`sec_flow_window_aggregate`、`sec_flow_feature_snapshot` 三类流量数据表。
- 将原始采集记录、时间窗口聚合结果和归一化特征分层保存，便于后续查询、评分和趋势展示。
- 实时流量监控采用独立会话链路，不绑定检测任务，也不强依赖任务流量三表。
- 监控页面展示报文、字节、会话、协议、DNS/HTTP/TLS 事件、突发分、扫描分和行为风险趋势，达到阈值后生成监控来源预警。

### 1.7 态势展示与系统管理

- 总览页展示任务统计、风险分布、风险趋势、来源覆盖、地理风险和流量趋势。
- 历史页合并任务记录和预警记录，便于按时间线回溯检测活动。
- 预警中心支持任务预警和实时流量监控预警的列表、详情和证据查看。
- 安全配置页支持评分阈值、权重、数据源开关、流量模式、抓包网卡和邮件字段配置。
- 使用 Vue 3、Element Plus 和 ECharts 完成后台管理界面和风险数据可视化。

## 2. 架构与工程成果

### 2.1 前后端分层

- 后端按 `router → api/v1 → service → repository → model` 分层。
- 路由层负责接口分组和中间件挂载，API 层负责参数绑定和统一响应，Service 层负责任务编排与规则处理，Repository 层负责数据访问。
- 前端按 `api`、`router`、`pinia`、`view` 和复用组件组织，统一使用 Axios 实例处理令牌注入和错误响应。
- 采用 `system + security` 双域结构，隔离系统管理能力与安全分析业务。

### 2.2 缓存、事务与降级

- MySQL 作为任务、画像、特征、评分、预警、流量和审计数据的主存储。
- Redis 用于总览统计和安全配置缓存；Redis 关闭、初始化失败或读写失败时回退到数据库，不阻断核心业务。
- 任务结果涉及多张关联表，使用事务保证画像、特征、评分、预警和流量结果的一致性。
- 删除任务时同步清理关联评分、预警、画像、流量数据和相关缓存，避免产生孤立证据。
- 外部数据源采用超时、fallback 和降级说明机制，确保增强能力失败时主流程仍然可解释、可继续运行。

## 6. 面试讲述口径

### 6.1 项目最大亮点

项目不是单纯展示 IP 信息，而是把静态画像、信誉、攻击面和动态流量行为统一到风险评分和证据链中。面试时可以重点说明：系统不仅告诉用户“风险是多少”，还能够说明“哪些数据源和哪些行为导致了这个结果”。

### 6.2 项目最大难点

最大的难点是不同数据源的稳定性和依赖条件不同：GeoLite2 需要本地库，RDAP 依赖网络，Nmap 和 Npcap 依赖运行环境，pcap 解析还依赖输入文件。项目通过采集器抽象、超时控制、fallback、缓存降级、事务写入和状态说明，将增强能力与默认 IP 检测主链路解耦。

### 6.3 如果被追问“Redis 或 GeoLite2 不可用怎么办”

Redis 主要承担缓存功能，异常时回退到 MySQL 查询；GeoLite2 缺失时记录降级原因，并尝试通过 RDAP 补充注册信息。Nmap 不可用时回退到 Go 原生有限端口探测，流量能力不可用时保留任务结果和失败说明，不影响默认 IP 检测流程。

### 6.4 如果被追问“如何解释高风险”

可以从四类评分因子展开：基础画像是否命中高风险地区或托管 ISP，信誉源是否命中黑名单，开放端口和高危端口是否较多，流量中是否出现端口扫描、异常突发、DNS/HTTP/TLS 异常、方向性偏置或高熵载荷等行为信号。

## 7. 诚实边界与后续方向

### 当前边界

- 当前系统定位为轻量化、可演示和可扩展的安全分析平台，不是常驻式生产级流量探针。
- `online_capture` 依赖 Npcap、网卡名称和运行权限；当前采用短时采样，不宣称长期后台守护采集。
- Nmap、AbuseIPDB、RDAP 和 GeoLite2 属于增强或外部数据源，项目设计了降级路径，但具体数据质量取决于配置和运行环境。
- 当前评分模型是可配置的规则与加权模型，不应表述为已经训练完成的机器学习模型。
- 仓库中没有统一、稳定的线上吞吐量和性能基准，简历中不虚构并发量、准确率或响应时间。

### 可继续演进

- 引入任务队列、并发控制和限流，提升大量检测任务同时执行时的稳定性。
- 完善长期流量采集、Prometheus 指标、链路追踪和统一日志分析。
- 增加更多威胁情报源、协议解析器和可视化评分规则配置。
- 补充端到端测试、浏览器级回归测试和真实网络环境下的性能测试。
- 对敏感配置、外部数据源密钥和在线抓包权限进行更严格的生产化管理。
