# 功能说明

## 1. 文档定位

本文用于说明 `lightweight-ip-traffic-sa` 当前已经落地的主要功能、页面入口、后端链路、数据源采集方式、流量增强边界、评分计算公式和依据。文档面向项目演示、答辩说明、交付归档和后续开发维护。

当前系统不是空白骨架，而是已经形成“默认 IP 多特征主链路 + 流量增强链路 + 实时流量监控链路”的前后端分离项目。默认主链路围绕目标 IP 发起检测任务，完成基础画像、信誉风险、攻击面风险、行为风险、融合评分、预警生成、总览展示和历史回溯；流量增强链路用于补充离线 pcap、短时在线抓包和任务详情中的动态证据；实时流量监控链路用于独立网卡监听和预警，不绑定检测任务。

## 3. 登录鉴权与权限控制

系统域负责登录、退出、当前用户和用户管理。除 `POST /api/v1/system/login` 外，当前后端接口默认需要 JWT。前端通过 Axios 拦截器在请求头注入 `Authorization: Bearer <token>`，并在路由守卫中根据 `meta.roles` 控制页面访问。

角色边界如下：

| 角色 | 可用能力 |
|---|---|
| `ADMIN` | 所有安全域页面、用户管理、审计日志、任务创建和删除、安全配置、实时监控观察面板 |
| `MANAGER` | 安全域业务页面、任务创建和删除、安全配置、实时监控观察面板 |
| `USER` | 态势总览、任务列表与详情、历史、预警、个人实时流量监控 |

这个权限模型的重点是把“系统管理能力”和“安全业务查看能力”分开，避免普通用户直接修改评分阈值、数据源开关或账号状态。

## 4. 发起任务

发起任务是默认业务主链路的入口，接口为：

```http
POST /api/v1/tasks
```

请求主体以目标 IP 为核心：

```json
{
  "targetIp": "8.8.8.8",
  "requestedBy": "admin"
}
```

后端执行顺序如下：

1. 校验目标 IP、用户身份和角色权限。
2. 创建任务记录，生成任务编号。
3. 加载运行时安全配置，包括评分权重、风险阈值、数据源开关、缓存 TTL 和流量模式。
4. 执行数据采集流水线：基础画像、信誉、攻击面、流量行为。
5. 将原始采集结果归一化为评分因子和证据快照。
6. 按评分公式计算最终分数、风险等级和评分说明。
7. 当评分达到高风险阈值时生成预警记录。
8. 写入任务、基础画像、特征快照、评分、预警和流量相关表。
9. 清理总览缓存，使首页统计尽快反映新任务。

任务详情页会展示基础画像、来源链、证据项、评分因子、流量增强结果、评分说明和预警摘要。当前删除任务接口也会删除关联流量、评分和预警记录，避免详情残留孤立证据。

## 5. 数据源采集

### 5.1 基础画像：GeoLite2 + RDAP

基础画像由 `realBaseInfoSourceProvider` 负责，当前默认策略是离线优先、在线补充：

1. 优先读取本地 `GeoLite2 Country / City / ASN` mmdb 文件，提取国家、地区、城市、经纬度、时区、精度半径、ASN 和组织信息。
2. 再调用 RDAP 端点补充注册组织、网段、联系人等注册信息。
3. RDAP 默认先访问 `https://rdap.org/ip/`，失败后轮询 ARIN、RIPE、APNIC、AFRINIC、LACNIC 备用端点。
4. GeoLite2 或 RDAP 失败时不会阻断任务，只在 `rawPayload.degraded` 和 `degradeReasons` 中记录降级原因。

采用 GeoLite2 的原因是它适合本地部署、低依赖、可重复演示；采用 RDAP 的原因是它是标准化注册数据访问协议，可解释目标 IP 所属注册资源。GeoLite2 参考 MaxMind GeoLite2 官方文档，RDAP 查询格式参考 RFC 7482 / RFC 9082。

### 5.2 信誉采集：本地黑名单 + AbuseIPDB 增强

信誉采集当前分两层：

1. 本地黑名单 / CIDR 名单是默认主方案，文件为 `server/data/security/local-blacklist.txt`。
2. AbuseIPDB 是可选信誉增强源，默认关闭，配置完整且启用后才访问公网接口。

本地黑名单命中时使用条目内分数；未命中时使用中性默认分。当前默认配置中：

```yaml
localBlacklist:
  matchScore: 92
  defaultScore: 20
```

AbuseIPDB 返回 `abuseConfidenceScore` 后直接映射为信誉风险分；如果返回白名单标识且分数高于 20，则降为 20，避免可信目标被误报。外部源失败时只追加降级证据，不中断任务。

### 5.3 攻击面采集：有限端口探测 + Nmap 原型

默认攻击面能力采用 Go 原生有限 TCP 端口探测，当前配置端口为：

```yaml
ports: [22, 80, 443, 445, 3389, 8080]
```

探测过程使用受控并发和短超时，当前默认 `maxConcurrency = 3`、单端口超时 `800ms`。高危端口集合包括 `22`、`445`、`3389`。该设计刻意避免把重型扫描能力变成默认依赖，便于本地演示和答辩说明。

Nmap 属于攻击面增强原型能力。配置中存在 `nmapEnabled`、`nmapPath`、`nmapTimeoutSeconds`，但工程边界仍是增强和回退：Nmap 不可用或失败时，系统回退到有限端口探测。

### 5.4 流量采集：sample / offline_pcap / online_capture / disabled

流量采集由 `RealFlowCollector` 和多种 `FlowParser` 承接，模式来自 `security.source.flow.mode`：

| 模式 | 含义 | 当前定位 |
|---|---|---|
| `disabled` | 关闭流量维能力 | 不进入默认来源链和评分说明 |
| `sample` | 样本画像原型 | 用于演示流量能力，不代表真实抓包 |
| `offline_pcap` | 离线 pcap / pcapng 文件解析 | 已接入 gopacket 解析、特征提取和落库 |
| `online_capture` | 短时在线抓包 | 基于 Npcap SDK + gopacket/pcap，依赖网卡权限 |

流量增强的关键边界是：它增强任务详情、历史、总览趋势和联合判定说明，但不是所有任务的默认前置条件。缺少 pcap 文件、网卡名、权限或解析失败时，系统记录失败状态和错误模型，不阻断 IP 主链路。

## 6. 流量增强

### 6.1 离线 pcap 解析

离线解析入口读取配置中的 `pcapFilePath`。当文件存在且可读取时，使用 gopacket 解析报文并生成：

| 指标 | 说明 |
|---|---|
| `packetCount` / `matchedPacketCount` | 总报文数、与目标 IP 相关的报文数 |
| `byteCount` | 目标相关字节数 |
| `sessionCount` | 双向会话数量 |
| `protocolCounts` | 协议分布 |
| `portCounts` / `peerCounts` | 端口和对端 IP 分布 |
| `peakPps` / `burstScore` | 峰值包速率与突发评分 |
| `scanScore` | 端口扫描倾向评分 |
| `dnsTopQuestions` | DNS 高频查询名 |
| `httpHostHints` / `httpMethodHints` / `httpStatusHints` | HTTP 主机、方法、状态线索 |
| `tlsHandshakeHints` / `tlsVersionHints` | TLS SNI 与版本线索 |
| `applicationSignals` | 应用层摘要信号 |
| `directionalityIndicators` | 入站 / 出站方向性偏置 |
| `portDensityIndicators` | 目标端口密度、唯一端口数、高危端口数 |
| `payloadEntropyIndicators` | 高熵载荷数量、平均熵、相关对端 |

离线 pcap 可以形成可回溯证据：采集记录、窗口聚合、特征快照、任务详情流量卡片、总览趋势和历史摘要。

### 6.2 在线抓包

在线抓包依赖可用网卡和本机抓包权限。安全配置页提供网卡枚举接口：

```http
GET /api/v1/configs/security/flow-interfaces
```

当模式为 `online_capture` 且提供网卡名时，系统会执行短时抓包并走与离线 pcap 类似的解析和指标生成链路。在线抓包不是常驻守护进程，当前边界是短时采样、真实落库、页面承接和失败可解释。

### 6.3 实时流量监控

实时流量监控是独立链路，不绑定任务 ID，也不写入任务流量三表。入口为：

```http
POST /api/v1/flow-monitor/sessions
GET  /api/v1/flow-monitor/sessions/current
GET  /api/v1/flow-monitor/sessions/:id
POST /api/v1/flow-monitor/sessions/:id/stop
GET  /api/v1/flow-monitor/observer-panel
```

监控会话按固定刷新间隔采样，展示报文数、字节数、会话数、行为风险、突发分、扫描分、DNS/HTTP/TLS 事件、协议分布和指标趋势。若行为风险达到高风险阈值，会在预警中心创建来源为实时监控的预警记录。为避免重复告警，代码中使用预警指纹和冷却时间去重。

## 7. 评分计算公式

### 7.1 评分因子

系统将采集结果归一化为四个 0 到 100 的风险分：

| 因子 | 代码字段 | 含义 |
|---|---|---|
| 基础属性风险 | `WhoisRiskScore` | 地理、ASN、ISP、注册信息带来的基础画像风险 |
| 信誉风险 | `ReputationScore` | 本地黑名单、AbuseIPDB 等信誉数据源给出的风险 |
| 攻击面风险 | `AttackSurfaceRisk` | 开放端口数、高危端口数、地理风险标记 |
| 行为风险 | `BehaviorRisk` | 流量解析得出的扫描、突发、协议、方向性、端口密度、高熵等动态行为风险 |

### 7.2 基础属性风险

当前代码公式：

```text
WhoisRisk = 25
          + GeoRiskCountry ? 30 : 0
          + ISP contains "hosting" ? 15 : 0
```

说明：

1. `25` 是基础不确定性分，表示仅凭 IP 归属无法证明安全。
2. 地理风险国家加分用于表达区域性安全治理、误用集中度、访问策略等工程经验风险。
3. 托管类 ISP 加分用于表达云主机、VPS、代理出口等更容易被滥用的基础设施风险。

### 7.3 信誉风险

当前公式：

```text
ReputationRisk = 数据源返回的信誉风险分
```

本地黑名单命中时：

```text
ReputationRisk = matchedEntry.score 或 localBlacklist.matchScore
```

未命中时：

```text
ReputationRisk = localBlacklist.defaultScore
```

AbuseIPDB 启用且成功时：

```text
ReputationRisk = abuseConfidenceScore
如果 isWhitelisted = true 且 ReputationRisk > 20，则 ReputationRisk = 20
```

### 7.4 攻击面风险

当前代码公式：

```text
AttackSurfaceRisk = OpenPortCount * 4
                  + HighRiskPortCount * 15
                  + GeoRiskFlag ? 10 : 0

AttackSurfaceRisk = min(AttackSurfaceRisk, 100)
```

说明：

1. 开放端口越多，可达服务越多，攻击面越大。
2. `22`、`445`、`3389` 等远程管理或横向移动相关端口权重更高。
3. 地理风险标记只做小幅修正，避免地理属性压过真实可达服务。

### 7.5 行为风险

流量行为风险来自流量解析器。离线 pcap / 在线抓包的主要公式为：

```text
BehaviorRisk = 4                                // 命中目标流量
             + Σ AnomalyCandidate.Score
             + BurstScore * 0.08
             + ScanScore * 0.12
             + DNSEventCount >= 40 ? 3 : 0
             + HTTPEventCount >= 20 ? 2 : 0
             + TLSEventCount >= 20 ? 2 : 0
             + HighEntropyPacketCount >= 24 ? 4 : 0
             + DirectionBias >= 0.92 ? 4 : 0
             + UniqueTargetPortCount >= 10 ? 4 : 0
             + TargetPortDensity >= 3 ? 3 : 0
             + HighRiskTargetPortCount >= 2 ? 6 : 0

BehaviorRisk = min(BehaviorRisk, 100)
```

其中：

```text
BurstScore = min(PeakPPS * 2, 100)
ScanScore  = min(UniqueTargetPortCount * 2.5 + SynProbeCount * 1.2 + TcpResetCount * 0.2, 100)
```

异常候选规则包括：

| 候选项 | 触发条件 | 加分 |
|---|---:|---:|
| `port-scan-candidate` | 唯一目标端口数 >= 8 且 SYN 探测数 >= 8 | 42 |
| `dns-spike-candidate` | DNS 事件数 >= 60 且唯一目标端口数 >= 4 | 14 |
| `icmp-probe-candidate` | ICMP 事件数 >= 30 | 20 |
| `tcp-reset-burst-candidate` | TCP RST 数 >= 40 | 8 |

### 7.6 加权融合

默认权重来自 `server/config.yaml`：

```yaml
weights:
  whoisWeight: 0.20
  reputationWeight: 0.35
  attackSurfaceWeight: 0.30
  behaviorWeight: 0.15
```

安全配置保存时会校验权重总和必须严格等于 `1.0000`。加权贡献计算为：

```text
BaseScore          = WhoisRisk * WhoisWeight
ReputationScore    = ReputationRisk * ReputationWeight
AttackSurfaceScore = AttackSurfaceRisk * AttackSurfaceWeight
BehaviorScore      = BehaviorRisk * BehaviorWeight
```

核心分：

```text
CoreScore = BaseScore + ReputationScore + AttackSurfaceScore + BehaviorScore
```

### 7.7 规则修正

加权分之后还有规则修正：

```text
RuleAdjustment = 0
GeoRiskFlag               => +6
HighRiskPortCount >= 3    => +5
BehaviorRisk >= 70        => +8
BehaviorRisk <= 10 且 flowMode = disabled => -2

RuleAdjustment = min(max(RuleAdjustment, -5), 15)
```

最终分：

```text
FinalScore = CoreScore + RuleAdjustment
FinalScore 保留两位小数
```

### 7.8 风险等级与预警

当前默认阈值：

```yaml
highRiskThreshold: 75
criticalRiskThreshold: 90
```

等级映射：

| 条件 | 风险等级 |
|---|---|
| `FinalScore >= criticalRiskThreshold` | `CRITICAL` |
| `FinalScore >= highRiskThreshold` | `HIGH` |
| `FinalScore >= 45` | `MEDIUM` |
| 其他 | `LOW` |

预警触发：

```text
IsAlertTriggered = FinalScore >= highRiskThreshold
```

实时流量监控不绑定任务，因此使用行为风险独立判定：

```text
MonitorScore = BehaviorRisk
MonitorRiskLevel = mapRiskLevel(MonitorScore)
MonitorAlert = MonitorScore >= highRiskThreshold
```

## 8. 评分依据与工程取舍

### 8.1 风险评估框架依据

NIST SP 800-30 将风险评估建立在威胁、脆弱性、影响和发生可能性等因素之上，强调识别威胁事件、脆弱性、影响和风险等级。本项目没有直接复刻 NIST 的组织级风险矩阵，而是把它工程化为 IP 画像场景下可采集、可解释、可落库的四类因子：基础属性、信誉、攻击面、流量行为。

### 8.2 攻击面指标依据

CVSS v4.0 的 Base Metrics 中包含 Attack Vector、Attack Complexity、Attack Requirements、Privileges Required、User Interaction 和影响指标。项目中的攻击面分不等同于 CVSS 漏洞分，而是借鉴“网络可达性、攻击复杂度、先决条件”这些思路，将开放端口数、高危端口、远程服务暴露作为轻量级攻击面代理指标。

### 8.3 权重依据

当前算法版本名为 `ahp-entropy-v1`，工程含义是“主观层次权重 + 行为信息量启发”。权重设计遵循以下原则：

1. 信誉风险权重最高，原因是黑名单和 AbuseIPDB 直接表达历史滥用证据，解释力较强。
2. 攻击面风险次高，原因是端口暴露体现当前可达服务和被攻击机会。
3. 基础属性风险保留中等权重，原因是地理、ASN、ISP 能辅助判断，但不应单独决定高风险。
4. 行为风险默认权重较低但可触发规则加分，原因是流量能力属于增强链路，样本、离线和在线抓包可用性受环境影响。

AHP 参考 Saaty 的层次分析法思想：先确定评价维度，再分配相对重要性权重。项目当前没有引入完整矩阵一致性检验，而是把权重做成配置项，便于答辩和部署时按场景调整。

### 8.4 流量特征依据

流量维度参考网络入侵检测和流量分类的常见工程特征：协议分布、会话数、包速率、SYN 探测、RST 异常、端口密度、DNS/HTTP/TLS 应用层线索和载荷熵。

1. Bro / Zeek 入侵检测思想强调从网络流量中抽取连接、协议和事件语义，而不是只看单包。
2. 流量分类研究常使用传输层统计、端口、协议和应用层线索来识别行为模式。
3. Shannon 信息熵用于衡量载荷字节分布的不确定性，高熵载荷可作为压缩、加密、隧道或混淆行为的辅助信号。
4. TLS SNI、DNS 查询名、HTTP Host 和方法都是应用层可解释线索，分别对应 RFC 8446 / RFC 6066、DNS 协议和 HTTP 协议语义。

因此，本项目没有把单一流量指标直接判定为恶意，而是采用“异常候选 + 突发分 + 扫描分 + 应用层线索 + 方向性 + 端口密度 + 熵指标”的组合方式，并把最终行为风险限制在 0 到 100。

### 8.5 降级与缓存依据

数据源失败不阻断任务，是为了满足演示系统和本地部署的稳定性：

1. GeoLite2 缺库时保留 UNKNOWN 字段并记录降级原因。
2. RDAP 超时或失败时继续使用已有基础画像。
3. AbuseIPDB 未配置、超时或失败时回退本地黑名单分。
4. Nmap、pcap、在线抓包失败时回退有限端口探测或记录流量失败状态。
5. 成功结果可以缓存，失败结果不作为可信数据长期缓存。

这种策略符合轻量化系统的目标：优先保证主链路可演示、可解释、可回溯，再逐步增强真实数据能力。

## 9. 页面功能讲解

### 9.1 态势总览

总览页聚合任务数、高风险数、严重风险数、预警数、今日检测数、暴露任务数、高危端口任务数、风险分布、趋势、来源覆盖和流量趋势。Redis 可用时，总览摘要使用短 TTL 缓存，任务创建成功后主动清理缓存。

总览页适合答辩时作为第一屏展示：先说明系统整体风险态势，再下钻到具体任务和预警。

### 9.2 检测任务

任务页用于发起目标 IP 检测、按 IP / 状态 / 风险等级筛选、按创建时间或评分排序。任务详情页展示：

1. 基本信息：任务编号、目标 IP、状态、创建人、开始和结束时间。
2. 基础画像：国家、地区、城市、ISP、ASN、RDAP 注册信息。
3. 来源链：基础画像、信誉、攻击面、流量来源链。
4. 证据项：每个数据源给出的解释性证据。
5. 评分因子：原始分、权重、贡献值、展示依据。
6. 流量增强：采集记录、窗口趋势、协议和应用层线索。
7. 预警摘要：命中阈值时展示预警内容和发送状态。

### 9.3 检测历史

历史页不是单表直出，而是合并任务记录和预警记录后统一分页展示。这样可以按时间线说明“检测发生了什么、是否触发预警、流量增强是否存在证据”。

### 9.4 预警中心

预警中心展示任务预警和实时流量监控预警。预警详情包含关联目标、风险等级、通知渠道、发送状态、评分摘要和证据上下文。当前通知渠道默认为 `SYSTEM`，即系统内记录，不依赖第三方通知服务。

### 9.5 安全配置

安全配置页用于维护：

1. 高风险阈值和严重风险阈值。
2. 四类评分权重。
3. GeoLite2、RDAP、本地黑名单、AbuseIPDB、攻击面探测、Nmap、流量模式等开关和参数。
4. 在线抓包网卡枚举和流量模式切换。

配置保存后会同步数据库、运行时内存配置和缓存。评分权重会校验总和为 1，避免页面误配置导致评分失真。

### 9.6 实时流量监控

实时流量监控页用于启动、查看和停止个人监控会话。管理员还可以进入观察面板查看用户会话汇总。该能力适合演示“短时网络行为观察”和“独立流量预警”，但它不是默认检测任务的前置条件。

## 10. 参考文献与资料

1. NIST, [SP 800-30 Rev. 1: Guide for Conducting Risk Assessments](https://csrc.nist.gov/pubs/sp/800/30/r1/final). 用于风险评估总体思路，包括威胁、脆弱性、影响和风险等级。
2. FIRST, [Common Vulnerability Scoring System v4.0 Specification](https://www.first.org/cvss/specification-document). 用于攻击面和可利用性指标设计参考。
3. RFC Editor, [RFC 7482: Registration Data Access Protocol Query Format](https://www.rfc-editor.org/rfc/rfc7482). 用于 RDAP 查询格式依据。
4. IETF, [RFC 9082: Registration Data Access Protocol Query Format](https://www.ietf.org/rfc/rfc9082.pdf). RFC 7482 的后续更新，用于 RDAP 查询格式补充依据。
5. MaxMind, [GeoLite Databases and Web Services](https://dev.maxmind.com/geoip/geoip2/geolite2/). 用于 GeoLite2 离线 IP 地理与 ASN 数据源说明。
6. RFC Editor, [RFC 8446: The Transport Layer Security Protocol Version 1.3](https://www.rfc-editor.org/rfc/rfc8446.html). 用于 TLS 握手和 SNI 线索解释。
7. C. E. Shannon, [A Mathematical Theory of Communication](https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf), 1948. 用于载荷熵指标的理论基础。
8. V. Paxson, [Bro: A System for Detecting Network Intruders in Real-Time](https://www.usenix.org/legacy/publications/library/proceedings/sec98/full_papers/paxson/paxson.pdf), USENIX Security 1998. 用于基于网络事件和协议语义做入侵检测的设计参考。
9. A. W. Moore and D. Zuev, [Internet Traffic Classification Using Bayesian Analysis Techniques](https://www.cl.cam.ac.uk/~awm22/publications/2005-Moore-Zuev-Bayesian-Analysis.pdf), SIGMETRICS 2005. 用于流量统计特征和分类思路参考。
10. T. L. Saaty, *The Analytic Hierarchy Process*, 1980. 用于多指标权重分配思想参考；本项目采用配置化权重，没有实现完整 AHP 一致性检验。
