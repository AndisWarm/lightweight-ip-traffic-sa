### 一、评分算法整体框架

该评分算法是**多维度加权 + 规则调整**的综合风险评分模型，核心流程分为 5 步：

1. **数据采集**：收集 IP 的基础信息、信誉、攻击面、流量行为四类原始数据；
2. **特征归一化**：将原始数据转化为标准化的风险分数；
3. **加权计算核心分**：对四类基础风险分按配置权重求和；
4. **规则调整**：基于业务规则对核心分做额外加减；
5. **风险等级映射 + 告警决策**：根据最终分数判定风险等级，触发告警（若超过阈值）。

### 二、核心评分步骤与依据

#### 1. 数据采集（评分的原始数据源）

通过 4 类 Collector 采集原始数据，是评分的基础：

| 采集器类型                       | 核心采集字段                                                 | 演示实现逻辑（Demo 版）                                      |
| :------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| BaseInfoCollector（基础信息）    | IP、国家 / 地区、运营商（ISP）、Whois 信息                   | 通过 IP 第一个八位组推断：如 192-224→中国北京，ISP 按八位组取模（%5=0→云托管，%3=0→区域骨干） |
| ReputationCollector（信誉）      | IP、信誉评分（0-100）                                        | 基于 IP 的 FNV 哈希值生成 30~85 分（30 + hash%55）           |
| AttackSurfaceCollector（攻击面） | 开放端口数、高危端口数、地理风险标记（RU/KP 为 true）        | 哈希值生成：开放端口数 = hash%12+1，高危端口数 =(hash/13)%4；地理风险 = 国家为 RU/KP 时为 true |
| FlowCollector（流量行为）        | 行为风险分（0-100）、流量指标（报文 / 会话数、DNS/HTTP/TLS 事件等） | 演示版通过 sampleFlowParser 生成模拟流量数据，行为风险分限制在 0-100 |

#### 2. 特征归一化（原始数据→标准化风险分）

通过`DefaultFeatureNormalizer.Normalize`将采集数据转化为可计算的风险分数，核心生成 3 类关键分数：

##### （1）Whois 风险分（基础信息风险）

```go
func computeWhoisRiskFromCollected(baseInfo BaseInfoCollectedData) float64 {
    score := 25.0
    if isGeoRiskCountry(baseInfo.Country) { // 地理风险国家（RU/KP等）
        score += 30
    }
    if strings.Contains(strings.ToLower(baseInfo.ISP), "hosting") { // 托管类ISP
        score += 15
    }
    return score
}
```

- 基础分：25 分；
- 加分项：地理风险国家（+30）、托管类 ISP（+15）；
- 示例：俄罗斯 + 云托管 ISP → 25+30+15=70 分。

##### （2）攻击面风险分

```go
func computeAttackSurfaceRiskFromCollected(attack AttackSurfaceCollectedData) float64 {
    score := float64(attack.OpenPortCount*4 + attack.HighRiskPortCount*15)
    if attack.GeoRiskFlag { // 地理风险标记
        score += 10
    }
    if score > 100 { // 上限100
        return 100
    }
    return score
}
```

- 基础计算：开放端口数 ×4 + 高危端口数 ×15；
- 加分项：地理风险标记为 true（+10）；
- 上限：100 分（超过则取 100）。

##### （3）行为风险分

直接复用流量采集的`BehaviorRiskScore`，限制在 0-100 之间（保留两位小数）：

```go
func computeBehaviorRisk(flow FlowCollectedData) float64 {
    if flow.BehaviorRiskScore < 0 {
        return 0
    }
    if flow.BehaviorRiskScore > 100 {
        return 100
    }
    return round2(flow.BehaviorRiskScore)
}
```

#### 3. 核心分数计算（加权求和）

通过`WeightedScoreCalculator.Calculate`实现，核心是**四类风险分按配置权重求和**：

```go
// 从归一化特征的ScoreFactors中提取各类贡献值
for _, factor := range normalized.ScoreFactors {
    switch factor.Key {
    case "whois":
        baseScore += factor.Contribution // 基础信息权重×Whois风险分
    case "reputation":
        reputationScore += factor.Contribution // 信誉权重×信誉分
    case "attack_surface":
        attackSurfaceScore += factor.Contribution // 攻击面权重×攻击面风险分
    case "behavior":
        behaviorScore += factor.Contribution // 行为权重×行为风险分
    }
}
```

- 权重配置来源：`cfg.Weights`（WhoisWeight/ReputationWeight/AttackSurfaceWeight/BehaviorWeight）；
- 示例：若 Whois 权重 0.2、Whois 风险分 70 → 基础分贡献 = 70×0.2=14。

#### 4. 规则调整（额外加减分）

通过`calculateRuleAdjustmentValue`对核心分做调整，规则如下（上限 + 15，下限 - 5）：

| 调整规则                             | 分值变化 | 说明                      |
| :----------------------------------- | :------- | :------------------------ |
| 地理风险标记为 true（RU/KP）         | +6       | 高风险地区额外加分        |
| 高危端口数≥3                         | +5       | 高危端口数量多额外加分    |
| 行为风险分≥70                        | +8       | 高行为风险额外加分        |
| 行为风险分≤10 且 流量模式为 disabled | -2       | 低行为风险 + 流量禁用减分 |

#### 5. 最终分数与风险等级

##### （1）最终分数

```go
scoreValue := baseScore + reputationScore + attackSurfaceScore + behaviorScore + ruleAdjustmentValue
```

所有分数通过`round2`保留两位小数（`float64(int(value*100+0.5)) / 100`）。

##### （2）风险等级映射

```go
func mapRiskLevel(score float64, runtimeConfig config.SecurityConfig) string {
    switch {
    case score >= runtimeConfig.CriticalRiskThreshold: // 致命阈值
        return "CRITICAL"
    case score >= runtimeConfig.HighRiskThreshold: // 高风险阈值
        return "HIGH"
    case score >= 45: // 中风险
        return "MEDIUM"
    default: // 低风险
        return "LOW"
    }
}
```

#### 6. 告警决策

通过`ThresholdAlertDecider.Decide`判断是否告警：

- 触发条件：最终分数≥高风险阈值（`score.IsAlertTriggered = scoreValue >= cfg.HighRiskThreshold`）；
- 告警内容：包含 IP、任务编号、评分、风险原因（如 “基础属性风险 70.00；信誉风险 85.00；攻击面风险 52.00；行为风险 60.00”）。

### 三、评分依据总结

| 评分维度     | 核心依据                                                     | 权重 / 调整规则                        |
| :----------- | :----------------------------------------------------------- | :------------------------------------- |
| 基础信息风险 | 地理风险国家（RU/KP）、ISP 类型（托管类）                    | 配置项 WhoisWeight                     |
| 信誉风险     | 第三方 / 演示生成的信誉分（30~85）                           | 配置项 ReputationWeight                |
| 攻击面风险   | 开放端口数、高危端口数、地理风险标记                         | 配置项 AttackSurfaceWeight + 地理 + 10 |
| 行为风险     | 流量行为风险分（0-100）、流量指标（报文 / 会话数、DNS/HTTP/TLS 事件等） | 配置项 BehaviorWeight                  |
| 规则调整     | 地理风险、高危端口数≥3、高行为风险、低行为风险 + 流量禁用    | 上限 + 15，下限 - 5                    |
