# 04. 数据源采集：四维数据从哪里来

## 一、本章要解决的问题

系统要评分，就得有数据。数据从哪来？为什么有的用本地文件，有的调外部 API？外部服务挂了怎么办？

## 三、基础画像：GeoLite2 + RDAP

### GeoLite2 是什么？

MaxMind 公司提供的离线 IP 地理数据库，文件格式是 `.mmdb`。项目里放在 `server/data/geoip/`：

```
GeoLite2-Country.mmdb   # 国家级别
GeoLite2-City.mmdb      # 城市级别
GeoLite2-ASN.mmdb       # ASN（自治系统号）和 ISP
```

**查询流程**：

```go
// server/service/security/p0_source_providers.go 伪代码
func queryGeoLite2(ip string, cfg GeoLite2Config) (GeoLite2Lookup, error) {
    // 1. 打开 mmdb 文件
    countryDB, _ := geoip2.Open(cfg.CountryDBPath)
    cityDB, _ := geoip2.Open(cfg.CityDBPath)
    asnDB, _ := geoip2.Open(cfg.ASNDBPath)

    // 2. 查询
    country, _ := countryDB.Country(net.ParseIP(ip))
    city, _ := cityDB.City(net.ParseIP(ip))
    asn, _ := asnDB.ASN(net.ParseIP(ip))

    // 3. 组装结果
    return GeoLite2Lookup{
        Country:  country.Country.IsoCode,      // "CN"
        Region:   city.Subdivisions[0].Names["en"],  // "Beijing"
        City:     city.City.Names["en"],        // "Beijing"
        ISP:      asn.AutonomousSystemOrganization,  // "China Telecom"
        ASN:      asn.AutonomousSystemNumber,   // 4134
        Latitude: city.Location.Latitude,
        Longitude: city.Location.Longitude,
    }, nil
}
```

**为什么用 GeoLite2？**
- ✅ 离线：不依赖网络，速度快（微秒级）
- ✅ 免费：MaxMind 提供免费的 GeoLite2（精度比付费版低，但够用）
- ✅ 稳定：不会因为外部 API 挂了而失败

**缺点**：
- 精度有限：免费版只能到城市级，不能到街道
- 更新滞后：IP 地址段会变动，mmdb 文件要定期更新

### RDAP 是什么？

RDAP（Registration Data Access Protocol）是查询 IP 注册信息的标准协议，替代老的 WHOIS。

**查询流程**：

```go
// 伪代码
func queryRDAP(ip string, cfg RDAPConfig) (RDAPLookup, error) {
    // 1. 先访问主端点
    url := fmt.Sprintf("https://rdap.org/ip/%s", ip)
    resp, err := http.Get(url)

    // 2. 失败时轮询备用端点
    if err != nil {
        for _, backupURL := range cfg.BackupBaseURLs {
            url = fmt.Sprintf("%s%s", backupURL, ip)
            resp, err = http.Get(url)
            if err == nil {
                break
            }
        }
    }

    // 3. 解析 JSON
    var result RDAPResponse
    json.NewDecoder(resp.Body).Decode(&result)

    return RDAPLookup{
        OrgName: result.Entities[0].VCardArray[1][1][3],  // 组织名
        CIDR:    result.CIDR0CIDRs[0].V4Prefix,           // 网段
    }, nil
}
```

**为什么用 RDAP 补充 GeoLite2？**
- GeoLite2 告诉你"这个 IP 在哪里"
- RDAP 告诉你"这个 IP 属于谁、归谁管"

**降级策略**：

```go
if geoLite2失败 && rdap失败 {
    // 不让任务失败，记录降级原因
    rawPayload["degraded"] = true
    rawPayload["degradeReasons"] = []string{"geolite2_failed", "rdap_failed"}
}
```

## 四、信誉风险：本地黑名单 + AbuseIPDB

### 本地黑名单

文件：`server/data/security/local-blacklist.txt`

格式：

```
# 注释
1.2.3.4         # 单个 IP
5.6.7.0/24      # CIDR 网段
```

加载逻辑：

```go
func loadLocalBlacklist(filePath string) ([]BlacklistEntry, error) {
    lines, _ := os.ReadFile(filePath)
    var entries []BlacklistEntry
    for _, line := range lines {
        line = strings.TrimSpace(line)
        if strings.HasPrefix(line, "#") {
            continue  // 跳过注释
        }
        if strings.Contains(line, "/") {
            // CIDR 网段
            _, cidr, _ := net.ParseCIDR(line)
            entries = append(entries, BlacklistEntry{CIDR: cidr})
        } else {
            // 单个 IP
            entries = append(entries, BlacklistEntry{IP: net.ParseIP(line)})
        }
    }
    return entries, nil
}
```

**评分规则**：

```yaml
# config.yaml
localBlacklist:
  matchScore: 92      # 命中黑名单 → 信誉风险 92 分
  defaultScore: 20    # 未命中 → 信誉风险 20 分（中性分）
```

### AbuseIPDB

一个公开的 IP 信誉数据库，用户可以举报恶意 IP。

**API 调用**：

```go
func queryAbuseIPDB(ip string, cfg AbuseIPDBConfig) (AbuseIPDBLookup, error) {
    url := fmt.Sprintf("https://api.abuseipdb.com/api/v2/check?ipAddress=%s", ip)
    req, _ := http.NewRequest("GET", url, nil)
    req.Header.Set("Key", cfg.APIKey)

    resp, _ := http.DefaultClient.Do(req)
    var result AbuseIPDBResponse
    json.NewDecoder(resp.Body).Decode(&result)

    return AbuseIPDBLookup{
        AbuseConfidenceScore: result.Data.AbuseConfidenceScore,  // 0~100
        IsWhitelisted:        result.Data.IsWhitelisted,
        TotalReports:         result.Data.TotalReports,
    }, nil
}
```

**评分规则**：

```go
reputationScore = abuseConfidenceScore
if isWhitelisted && reputationScore > 20 {
    reputationScore = 20  // 白名单最高分 20，避免误报
}
```

**为什么本地黑名单是主方案，AbuseIPDB 是增强？**
- AbuseIPDB 需要 API Key，每天有调用次数限制
- AbuseIPDB 依赖公网访问，本地黑名单离线可用
- 本地黑名单可以自己维护（比如公司内部的黑名单）

## 五、攻击面：端口探测 + Nmap

### Go 原生 TCP 端口探测

```go
// server/service/security/p1_attack_surface_provider.go
func scanPorts(ip string, ports []int, maxConcurrency int, timeout time.Duration) []int {
    var openPorts []int
    var wg sync.WaitGroup
    sem := make(chan struct{}, maxConcurrency)  // 信号量控制并发

    for _, port := range ports {
        wg.Add(1)
        go func(p int) {
            defer wg.Done()
            sem <- struct{}{}         // 获取信号量
            defer func() { <-sem }()  // 释放信号量

            address := fmt.Sprintf("%s:%d", ip, p)
            conn, err := net.DialTimeout("tcp", address, timeout)
            if err == nil {
                conn.Close()
                openPorts = append(openPorts, p)
            }
        }(port)
    }
    wg.Wait()
    return openPorts
}
```

**配置**：

```yaml
attackSurface:
  ports: [22, 80, 443, 445, 3389, 8080]  # 只扫这 6 个端口
  maxConcurrency: 3                       # 最多 3 个并发
  timeoutMilliseconds: 800                # 单端口超时 800ms
```

**高危端口**：

```go
var highRiskPorts = map[int]bool{
    22:   true,  // SSH
    445:  true,  // SMB（勒索病毒常用）
    3389: true,  // RDP（远程桌面）
}
```

**为什么不扫全部 65535 个端口？**
- 太慢：65535 个端口 × 800ms = 最长 14 小时
- 太重：容易被目标防火墙识别为端口扫描并封锁
- 没必要：常见高危服务就那几个端口

### Nmap 增强

Nmap 是专业端口扫描工具，可以做：
- 全端口扫描
- 服务版本识别（`nmap -sV`）
- 操作系统指纹识别（`nmap -O`）

**调用方式**：

```go
func scanWithNmap(ip string, nmapPath string, timeout int) (NmapResult, error) {
    ctx, cancel := context.WithTimeout(context.Background(), time.Duration(timeout)*time.Second)
    defer cancel()

    cmd := exec.CommandContext(ctx, nmapPath, "-p-", "--min-rate", "1000", ip)
    output, err := cmd.Output()
    // 解析 nmap 输出...
}
```

**降级策略**：

```go
if nmapEnabled && nmap可用 {
    return scanWithNmap(...)
} else {
    return scanPorts(...)  // 回退到 Go 原生探测
}
```

## 七、采集器抽象：接口 + 超时 + 缓存

所有采集器都实现统一接口：

```go
type BaseInfoCollector interface {
    Collect(taskID uint64, targetIP string, cfg config.SecurityConfig) (BaseInfoCollectedData, error)
}
```

**为什么要抽象成接口？**
- 可以有多套实现：Demo 版、真实版、Mock 版
- 便于测试：单测时用 Mock 实现，不依赖真实数据源

### 超时控制

每个采集步骤都有 2 秒超时：

```go
const collectorTimeout = 2 * time.Second

func runCollectorStep[T any](...) {
    resultCh := make(chan collectorResult[T], 1)

    go func() {
        value, err := execute()
        resultCh <- collectorResult[T]{value, err}
    }()

    select {
    case result := <-resultCh:
        return result.value, result.err
    case <-time.After(timeout):
        return zero, CollectorError{Kind: CollectorErrorTimeout}
    }
}
```

**为什么用 channel + select？**
- Go 的 HTTP 客户端没有内置超时（老版本）
- 用 channel 可以在 goroutine 里执行，主 goroutine 用 select 等结果或超时

### 缓存

每个采集结果都缓存，key 包含目标 IP + 数据源 + 配置版本：

```go
cacheKey := utils.BuildCollectorCacheKey(targetIP, sourceName, configVersion)
// 例如：collector:8.8.8.8:geolite2:wh=0.20|rep=0.35|atk=0.30|beh=0.15|...
```

**为什么 key 要包含配置版本？**
- 如果用户改了权重或阈值，缓存的结果应该失效
- 配置版本字符串包含所有关键配置，改任何一项都会导致缓存 key 变化

**TTL**：默认 30 分钟（`collectorTTLSeconds: 1800`）。

**失败结果不缓存**：

```go
if shouldCacheCollectorValue(result.value) {
    utils.CacheSetJSON(cacheKey, result.value, cacheTTL)
} else {
    log.Printf("采集步骤命中降级结果，按失败不缓存处理")
}
```

## 八、降级策略总结

| 数据源 | 失败时怎么办 | 是否阻断任务 |
|---|---|---|
| GeoLite2 | 记录降级原因，字段留空 | ❌ 不阻断 |
| RDAP | 记录降级原因，用 GeoLite2 数据 | ❌ 不阻断 |
| 本地黑名单 | 使用默认分 20 | ❌ 不阻断 |
| AbuseIPDB | 回退到本地黑名单 | ❌ 不阻断 |
| 端口探测 | 返回 0 个开放端口 | ❌ 不阻断 |
| Nmap | 回退到 Go 原生探测 | ❌ 不阻断 |
| 流量采集 | 标记失败状态 | ❌ 不阻断 |

**核心原则**：增强能力可降级，主链路永不阻断。

## 九、本章 Q&A

**Q：为什么不直接用商业威胁情报 API（如 VirusTotal）？**
A：
1. 商业化 API 要付费
2. 有调用次数限制
3. 教学项目重点在架构和流程，不在数据源本身的权威性

**Q：GeoLite2 数据库多久更新一次？**
A：MaxMind 官方每周更新一次。项目里可以配置 `geoipupdate` 工具自动更新。

**Q：如果目标在内网（如 192.168.1.1），GeoLite2 和 RDAP 都查不到怎么办？**
A：会返回空结果，记录降级原因。评分时基础画像维度得分较低，但不影响其他维度。

**Q：本地黑名单怎么维护？**
A：手工编辑 `local-blacklist.txt`，或者写脚本从开源威胁情报源（如 abuse.ch）同步。

**Q：端口探测会不会被目标防火墙识别为攻击？**
A：会。所以：
- 只扫 6 个常见端口，不全端口扫
- 加了并发限制和超时
- 文档里明确说明这是教学演示，不要用于未授权扫描

**Q：如果所有数据源都失败了，任务会 FAILED 吗？**
A：不会。只要参数校验通过，任务就会继续执行。所有数据源失败时，四个维度得分都较低，最终评分也低，但任务状态是 SUCCESS，只是结果可能不准。
