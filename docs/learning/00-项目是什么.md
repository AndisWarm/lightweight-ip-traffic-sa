# 00. 项目是什么 + 技术栈全景

## 一、一句话介绍

> 这是一个**围绕 IP 地址做安全风险评分**的 Web 系统：用户输入一个 IP，系统从四个维度（基础画像 / 信誉 / 攻击面 / 流量行为）采集数据，用加权评分模型算出 0~100 的风险分，给出 LOW / MEDIUM / HIGH / CRITICAL 等级，超过阈值就生成预警。

这句话里每个关键词都是面试的引子：
- **IP 地址** → 安全领域最常见的分析对象
- **四个维度** → 说明你不是单一指标，而是多源融合
- **加权评分模型** → 引到算法设计
- **预警** → 引到业务流程闭环

## 二、项目全名 / 仓库名

`lightweight-ip-traffic-sa`
- `lightweight` = 轻量化（不依赖重型安全平台、不依赖常驻 Agent）
- `ip-traffic` = IP + 流量两大分析维度
- `sa` = Situation Awareness，**态势感知**

> 态势感知（Situation Awareness）是安全领域的术语，意思是"把各种来源的数据汇聚起来，让人对当前网络安全状态有整体认知"。

## 三、三档自我介绍口径

### 30 秒版（电梯演讲）

> 我做了一个轻量化的 IP 态势感知系统，技术栈是 Go + Gin + Gorm + MySQL + Redis 后端，Vue3 + Element Plus + ECharts 前端。核心是给任意 IP 算一个 0~100 的风险分：从 GeoLite2 查地理、从黑名单查信誉、扫端口看攻击面、用 gopacket 解析 pcap 看流量行为，四个维度按可配置权重加权，加规则修正，得出最终分和风险等级。系统支持任务异步执行、JWT 鉴权、角色权限、实时流量监控，主链路全部落地。

### 2 分钟版（开场介绍）

在 30 秒基础上加：
- **业务闭环**：登录 → 创建任务 → 异步采集评分 → 总览/历史/预警 → 配置管理
- **架构亮点**：双域拆分（system + security）、分层（router → api → service → repository → model）
- **可靠性**：缓存降级、外部源 fallback、事务写入、JWT 黑名单
- **流量能力**：支持 pcap 离线解析和 Npcap 在线抓包，提取 DNS/HTTP/TLS/端口密度/方向性/载荷熵等特征

### 5 分钟版（深入讲解）

在 2 分钟基础上加：
- **评分公式**（背下来）：
  - `WhoisRisk = 25 + 地理风险(+30) + 托管ISP(+15)`
  - `AttackSurfaceRisk = 开放端口×4 + 高危端口×15 + 地理标记(+10)`，封顶 100
  - `FinalScore = Σ(四维风险×权重) + 规则修正(-5~+15)`
  - 默认权重：whois 0.20 / reputation 0.35 / attackSurface 0.30 / behavior 0.15
- **等级映射**：≥90 CRITICAL、≥75 HIGH、≥45 MEDIUM、其他 LOW
- **工程取舍**：为什么轻量化、为什么可降级、为什么流量是增强而不是硬依赖

## 五、为什么叫"轻量化"？

面试经常问。三个维度回答：

1. **部署轻量**：单 Go 二进制 + MySQL + Redis + 前端静态文件。Nmap / Npcap / AbuseIPDB 都是**可选**，缺失时系统照常运行。
2. **依赖轻量**：默认主链路只需要 GeoLite2 + 本地黑名单 + 端口探测。RDAP / AbuseIPDB / Nmap / Npcap 都是增强项，可配置开关。
3. **运行轻量**：不部署常驻流量探针，不维护长连接，不引入消息队列。流量分析是**按需触发**（任务或监控会话）。

## 六、为什么叫"态势感知"？

也是高频问题。

传统安全工具往往只看一个维度（比如只扫端口、只查黑名单）。本项目把**4 个维度**融合：
- 静态属性：这个 IP 在哪里、属于谁（GeoLite2/RDAP）
- 历史信誉：它过去干过坏事吗（黑名单/AbuseIPDB）
- 当前暴露：它现在开了多少端口（端口探测/Nmap）
- 动态行为：它现在正在干什么（流量分析）

把四维数据汇聚成分数、等级、预警、趋势图，让人对"这个 IP 当前有多危险"形成整体认知 —— 这就是态势感知。

## 七、项目的边界（诚实回答用）

面试官可能会试探你"吹没吹牛"，主动说清边界反而加分：

- ❌ 不是常驻流量探针 → 是按需短时采样
- ❌ 不是生产级 IDS/IPS → 是教学/演示级态势感知
- ❌ 评分模型不是机器学习 → 是可解释的加权 + 规则
- ❌ Nmap/Npcap/AbuseIPDB 不是默认依赖 → 是可选增强
- ✅ 主链路全部落地、可运行、可演示、可解释

## 八、本章 Q&A 预热

**Q：你的项目和商业态势感知产品（如奇安信、绿盟）有什么区别？**
A：商业产品是常驻探针 + 大数据平台 + 机器学习，部署在政企骨干网。我的项目是轻量化教学演示版本，聚焦"对一个 IP 做一次按需评估"，强调可解释性和部署简单。

**Q：为什么不做成机器学习评分？**
A：三个原因：
1. 数据集不够（没有标注好的恶意 IP 数据集）
2. 可解释性差（安全场景需要告诉用户"为什么是高危"）
3. 教学价值（加权模型可以在白板上手算）

**Q：项目最大的技术亮点？**
A：可解释的风险评分 + 全链路降级设计。每条评分都能拆到具体的因子和权重，每个外部依赖都有 fallback。
