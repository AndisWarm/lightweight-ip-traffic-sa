# 06. 流量增强：gopacket + pcap 解析

## 一、本章要解决的问题

前三章讲的数据源（GeoLite2、黑名单、端口探测）都是**静态**的：查库、读文件、扫端口。但一个 IP 现在是否在发起攻击，只能看**动态流量**。

本章讲：怎么用 gopacket 解析 pcap 文件和在线抓包，提取 DNS/HTTP/TLS/端口/载荷熵等特征，算出行为风险分。

## 二、什么是 pcap？

pcap（Packet Capture）是一种文件格式，用来保存网络数据包。Wireshark、tcpdump 抓包后保存的就是 `.pcap` 或 `.pcapng` 文件。

一个 pcap 文件长这样：

```
+------------+------------------+------------------+
| 全局头      | 数据包1          | 数据包2          |
| (24字节)   | (时间戳+长度+数据)| (时间戳+长度+数据)|
+------------+------------------+------------------+
```

每个数据包包含：
- 时间戳
- 原始字节（以太网帧 → IP 包 → TCP/UDP 段 → 应用层数据）

## 三、什么是 gopacket？

gopacket 是 Go 语言的 pcap 解析库，底层封装了 libpcap（C 库）。

**核心功能**：
1. 读 pcap 文件：`pcap.OpenOffline("file.pcap")`
2. 在线抓包：`pcap.OpenLive("eth0", 1600, true, pcap.BlockForever)`
3. 解码数据包：`packet := gopacket.NewPacket(data, layers.LayerTypeEthernet, gopacket.Default)`
4. 提取协议层：`packet.Layer(layers.LayerTypeTCP)`

## 四、四种流量模式

项目支持四种模式，配置在 `sec_security_config` 表的 `flow_mode` 字段：

| 模式 | 含义 | 依赖 | 场景 |
|---|---|---|---|
| disabled | 关闭流量采集 | 无 | 最小化部署 |
| sample | 样本模式（演示） | 无 | 答辩演示，不依赖真实流量 |
| offline_pcap | 解析 pcap 文件 | pcap 文件路径 | 离线分析、复盘历史攻击 |
| online_capture | 在线抓包 | Npcap + 网卡名 + 管理员权限 | 实时监控本机流量 |

## 五、离线 pcap 解析流程

### 1. 入口

```go
// server/service/security/p2_flow_gopacket_parser.go
func (p gopacketParser) Parse(ctx context.Context, req FlowParseRequest) (FlowParseResult, error) {
    // 1. 校验 pcap 文件路径
    if req.PcapFilePath == "" {
        return FlowParseResult{}, errors.New("pcap file path is empty")
    }
    if _, err := os.Stat(req.PcapFilePath); err != nil {
        return FlowParseResult{}, fmt.Errorf("pcap file not found: %w", err)
    }

    // 2. 打开文件
    handle, err := pcap.OpenOffline(req.PcapFilePath)
    if err != nil {
        return FlowParseResult{}, fmt.Errorf("open pcap failed: %w", err)
    }
    defer handle.Close()

    // 3. 逐包解析
    packetSource := gopacket.NewPacketSource(handle, handle.LinkType())
    for packet := range packetSource.Packets() {
        p.processPacket(packet, req.TargetIP, &result)
    }

    // 4. 生成指标
    result.ParsedMetrics = p.buildMetrics()
    return result, nil
}
```

### 2. 逐包解析

```go
func (p *gopacketParser) processPacket(packet gopacket.Packet, targetIP string, result *FlowParseResult) {
    // 提取网络层（IP）
    ipLayer := packet.Layer(layers.LayerTypeIPv4)
    if ipLayer == nil {
        return
    }
    ip, _ := ipLayer.(*layers.IPv4)

    // 判断是否和目标 IP 相关
    if ip.SrcIP.String() != targetIP && ip.DstIP.String() != targetIP {
        return  // 不相关，跳过
    }

    result.PacketCount++
    result.ByteCount += uint64(len(packet.Data()))

    // 提取传输层（TCP/UDP）
    if tcpLayer := packet.Layer(layers.LayerTypeTCP); tcpLayer != nil {
        tcp, _ := tcpLayer.(*layers.TCP)
        p.processTCP(tcp, ip, result)
    } else if udpLayer := packet.Layer(layers.LayerTypeUDP); udpLayer != nil {
        udp, _ := udpLayer.(*layers.UDP)
        p.processUDP(udp, ip, result)
    }

    // 提取应用层（DNS/HTTP/TLS）
    if dnsLayer := packet.Layer(layers.LayerTypeDNS); dnsLayer != nil {
        dns, _ := dnsLayer.(*layers.DNS)
        p.processDNS(dns, result)
    }
    // HTTP 和 TLS 没有现成 layer，要解析 payload
    if appLayer := packet.ApplicationLayer(); appLayer != nil {
        p.processApplicationLayer(appLayer, tcp, result)
    }
}
```

### 3. 提取的指标

| 指标 | 说明 | 用途 |
|---|---|---|
| packetCount / matchedPacketCount | 总报文数 / 与目标相关报文数 | 判断流量规模 |
| byteCount | 目标相关字节数 | 判断流量大小 |
| sessionCount | 双向会话数 | 判断连接数 |
| protocolCounts | 协议分布（TCP/UDP/ICMP/DNS/HTTP/TLS） | 判断流量类型 |
| portCounts / peerCounts | 端口分布、对端 IP 分布 | 判断扫描行为 |
| peakPps | 峰值包速率 | 判断突发流量 |
| burstScore | 突发评分 | `min(PeakPPS × 2, 100)` |
| scanScore | 扫描评分 | `min(UniqueTargetPortCount × 2.5 + SynProbeCount × 1.2 + TcpResetCount × 0.2, 100)` |
| dnsTopQuestions | DNS 高频查询名 | 判断 DNS 隧道/DGA |
| httpHostHints / httpMethodHints / httpStatusHints | HTTP Host、方法、状态码 | 判断 Web 攻击 |
| tlsHandshakeHints / tlsVersionHints | TLS SNI、版本 | 判断加密流量目的地 |
| applicationSignals | 应用层摘要信号 | 综合判断 |
| directionalityIndicators | 入站/出站方向性偏置 | 判断是攻击者还是被攻击 |
| portDensityIndicators | 目标端口密度、唯一端口数、高危端口数 | 判断端口扫描 |
| payloadEntropyIndicators | 高熵载荷数量、平均熵 | 判断加密/混淆/隧道 |

### 4. 会话跟踪

```go
type SessionKey struct {
    SrcIP   string
    DstIP   string
    SrcPort uint16
    DstPort uint16
    Protocol string
}

func (p *gopacketParser) processTCP(tcp *layers.TCP, ip *layers.IPv4, result *FlowParseResult) {
    // 构造会话 key（双向）
    key1 := SessionKey{ip.SrcIP.String(), ip.DstIP.String(), uint16(tcp.SrcPort), uint16(tcp.DstPort), "TCP"}
    key2 := SessionKey{ip.DstIP.String(), ip.SrcIP.String(), uint16(tcp.DstPort), uint16(tcp.SrcPort), "TCP"}

    if _, ok := result.Sessions[key1]; !ok {
        if _, ok := result.Sessions[key2]; !ok {
            result.SessionCount++
            result.Sessions[key1] = true
        }
    }

    // 统计 SYN 探测
    if tcp.SYN && !tcp.ACK {
        result.SynProbeCount++
    }
    // 统计 RST
    if tcp.RST {
        result.TcpResetCount++
    }
}
```

### 5. DNS 解析

```go
func (p *gopacketParser) processDNS(dns *layers.DNS, result *FlowParseResult) {
    result.DNSEventCount++
    for _, question := range dns.Questions {
        domain := string(question.Name)
        result.DNSQueryCount[domain]++
    }
}
```

### 6. HTTP 解析

```go
func (p *gopacketParser) processHTTP(payload []byte, result *FlowParseResult) {
    // 简单解析 HTTP 请求行
    lines := strings.Split(string(payload), "\r\n")
    if len(lines) == 0 {
        return
    }
    parts := strings.Split(lines[0], " ")
    if len(parts) >= 2 {
        method := parts[0]  // GET / POST / ...
        result.HTTPMethodCount[method]++
        result.HTTPEventCount++
    }
    // 解析 Host 头
    for _, line := range lines {
        if strings.HasPrefix(line, "Host: ") {
            host := strings.TrimPrefix(line, "Host: ")
            result.HTTPHostCount[host]++
            break
        }
    }
}
```

### 7. TLS 解析

TLS 握手包（ClientHello）里有 SNI（Server Name Indication），可以看出访问的域名：

```go
func (p *gopacketParser) processTLS(payload []byte, result *FlowParseResult) {
    // 判断是否是 TLS ClientHello
    if len(payload) < 5 || payload[0] != 0x16 {  // 0x16 = Handshake
        return
    }
    result.TLSEventCount++

    // 解析 SNI（省略复杂代码）
    sni := parseSNI(payload)
    if sni != "" {
        result.TLSSNICount[sni]++
    }
}
```

### 8. 载荷熵计算

熵（Entropy）是信息论概念，表示数据的"随机性"。加密、压缩、混淆的数据熵值高，明文数据熵值低。

```go
func calculateEntropy(data []byte) float64 {
    if len(data) == 0 {
        return 0
    }
    var freq [256]int
    for _, b := range data {
        freq[b]++
    }
    entropy := 0.0
    for _, count := range freq {
        if count > 0 {
            p := float64(count) / float64(len(data))
            entropy -= p * math.Log2(p)
        }
    }
    return entropy  // 0 ~ 8
}
```

**判断高熵**：

```go
if entropy > 7.0 {  // 阈值
    result.HighEntropyPacketCount++
}
```

**为什么高熵可疑？**
- 正常 HTTP/HTML 熵值 ~4-5
- 加密数据（TLS、VPN）熵值 ~7-8
- 恶意软件常用加密/混淆隐藏通信内容

## 六、行为风险分计算

综合所有指标，算出 0~100 的行为风险分：

```go
func (p *gopacketParser) calculateBehaviorRisk(metrics ParsedMetrics) float64 {
    score := 4.0  // 基础分（命中目标流量）

    // 1. 异常候选
    if metrics.UniqueTargetPortCount >= 8 && metrics.SynProbeCount >= 8 {
        score += 42  // port-scan-candidate
    }
    if metrics.DNSEventCount >= 60 && metrics.UniqueTargetPortCount >= 4 {
        score += 14  // dns-spike-candidate
    }
    if metrics.ICMPEventCount >= 30 {
        score += 20  // icmp-probe-candidate
    }
    if metrics.TcpResetCount >= 40 {
        score += 8   // tcp-reset-burst-candidate
    }

    // 2. 突发和扫描
    score += metrics.BurstScore * 0.08
    score += metrics.ScanScore * 0.12

    // 3. 事件数量阈值
    if metrics.DNSEventCount >= 40 {
        score += 3
    }
    if metrics.HTTPEventCount >= 20 {
        score += 2
    }
    if metrics.TLSEventCount >= 20 {
        score += 2
    }

    // 4. 高熵载荷
    if metrics.HighEntropyPacketCount >= 24 {
        score += 4
    }

    // 5. 方向性偏置
    if metrics.DirectionBias >= 0.92 {  // 92% 单向
        score += 4
    }

    // 6. 端口密度
    if metrics.UniqueTargetPortCount >= 10 {
        score += 4
    }
    if metrics.TargetPortDensity >= 3 {
        score += 3
    }
    if metrics.HighRiskTargetPortCount >= 2 {
        score += 6
    }

    if score > 100 {
        return 100
    }
    return score
}
```

## 七、在线抓包流程

和离线 pcap 类似，但数据源从文件变成网卡：

```go
func (p liveCaptureParser) Parse(ctx context.Context, req FlowParseRequest) (FlowParseResult, error) {
    // 1. 打开网卡
    handle, err := pcap.OpenLive(req.InterfaceName, 1600, true, pcap.BlockForever)
    if err != nil {
        return FlowParseResult{}, fmt.Errorf("open interface failed: %w", err)
    }
    defer handle.Close()

    // 2. 设置 BPF 过滤器（只抓目标 IP 的包）
    filter := fmt.Sprintf("host %s", req.TargetIP)
    handle.SetBPFFilter(filter)

    // 3. 抓包 N 秒
    timeout := time.Duration(req.TimeoutSeconds) * time.Second
    packetSource := gopacket.NewPacketSource(handle, handle.LinkType())

    timer := time.After(timeout)
    for {
        select {
        case packet := <-packetSource.Packets():
            p.processPacket(packet, req.TargetIP, &result)
        case <-timer:
            goto DONE
        }
    }
DONE:
    result.ParsedMetrics = p.buildMetrics()
    return result, nil
}
```

**为什么用 BPF 过滤器？**
- 网卡收到的包很多，大部分和目标 IP 无关
- BPF（Berkeley Packet Filter）在内核层过滤，性能高
- `host 8.8.8.8` 只保留源或目的是 8.8.8.8 的包

## 九、本章 Q&A

**Q：为什么不直接接入 Zeek（Bro）？**
A：Zeek 是专业 IDS，功能强大但：
1. 部署复杂（需要 Linux、依赖多）
2. 学习曲线陡（有自己的脚本语言）
3. 本项目定位是轻量化教学，gopacket 够用

**Q：pcap 文件从哪来？**
A：
1. Wireshark / tcpdump 抓包
2. 公开数据集（如 CICIDS2017、UNSW-NB15）
3. 自己写脚本生成

**Q：在线抓包为什么需要管理员权限？**
A：网卡抓包是底层操作，需要访问内核态网络栈。Windows 需要 Npcap 驱动 + 管理员，Linux 需要 root 或 CAP_NET_RAW 权限。

**Q：如果 pcap 文件里没有目标 IP 的流量怎么办？**
A：`matchedPacketCount` 为 0，`collection_status` 标记为 `NO_TARGET_TRAFFIC`，行为风险分为 0，任务继续。

**Q：为什么流量是增强能力而不是默认硬依赖？**
A：
1. pcap 文件不总是有
2. 在线抓包依赖权限和网卡
3. 样本模式只是演示，不代表真实流量

如果把流量作为硬依赖，没有 pcap 时任务就失败，不符合"轻量化"目标。
